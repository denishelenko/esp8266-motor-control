# Arduino IDE: пайка, прошивання та перевірка

Нові папки **09_NodeMCU_MotorServoLED / 10_WemosPro_MotorServoLED / 11_ESP32S3_MotorServoLED** містять автономні версії з кнопкою світла. Їхня окрема [інструкція та таблиця GPIO](../README_STANDALONE_LED.md). Варіанти 01–08 нижче залишені без LED.

## Яку папку відкривати

| Папка | Призначення | Профіль плати |
|---|---|---|
| 01_TwoESP_Controller | Сайт + передавач ESP-NOW, без підключених моторів | фактична ESP8266 |
| 02_TwoESP_Motor | Приймач ESP-NOW + L298N, без серво | фактична ESP8266 |
| 03_OneESP | NodeMCU v3: сайт + канал A L298N + серво | NodeMCU 1.0 (ESP-12E Module) |
| 04_Calibration | Окремий вимірювальний тест із сайту | фактична ESP8266 |
| 05_Motor_OneSecond_Test | Безкінечний стендовий тест, 20%, по 2 с в кожен бік | фактична ESP8266 |
| 06_TwoMotors_OneESP | Обидва мости L298N, однаковий PWM, без серво | фактична ESP8266 |
| 07_WemosD1MiniPro | Wemos: сайт + канал A L298N + серво | LOLIN(WEMOS) D1 mini Pro |
| 08_Board_Diagnostics | Лише Wi-Fi і Serial, не керує моторами/серво | фактична ESP8266 |

Відкривайте .ino всередині його однойменної папки. Не додавайте різні скетчі вкладками одного проєкту — отримаєте дублікати setup()/loop().
Розпакуйте архів цілком у звичайну доступну для запису папку, наприклад `C:/ArduinoProjects/esp8266-motor-control`, а не відкривайте з архіву.
Кожну папку 01–08 можна копіювати окремо разом з усіма її файлами.

## NodeMCU v3 — 03_OneESP

Драйвер L298N:
- D1 / GPIO5 → ENA.
- D2 / GPIO4 → IN1.
- D5 / GPIO14 → IN2.
- GND → спільний GND драйвера та джерела.
- VIN → стабілізовані 5 В (перевірте маркування саме вашої плати).

Сервопривід:
- D6 / GPIO12 → жовтий сигнал.
- Червоний → окреме достатньо потужне стабілізоване живлення серво, для першого тесту 5 В у межах специфікації моделі.
- Коричневий → спільний GND.

D1 від'єднайте від ENB. D7 не використовується.
Один або два паралельно підключені двигуни — на OUT1/OUT2 каналу A; сумарний пусковий/стопорний струм має вкладатися у реальні можливості драйвера та живлення.

## Wemos D1 mini Pro — 07_WemosD1MiniPro

Драйвер L298N:
- D1 / GPIO5 → ENA.
- D2 / GPIO4 → IN1.
- D6 / GPIO12 → IN2.
- GND → спільний GND.
- Контакт **5V** → стабілізовані 5 В.

Сервопривід:
- **D5 / GPIO14 → жовтий сигнал**.
- Червоний → живлення серво, як вище.
- Коричневий → спільний GND.

Порівняно з останньою NodeMCU-схемою D5 і D6 міняються ролями. D3/D4 тут не використовуються.
Якщо раніше серво було на D4 — перенесіть сигнал на D5; IN2 залишається на D6.

## Інші варіанти

02, 04, 05 за замовчуванням: **D1 → ENA; D2 → IN1; D5 → IN2; серво не керується**.
Це нова схема замість колишніх D6/D7/D8.
Якщо тестуєте вже спаяний Wemos зі схемою 07: у .ino для 04 або 05 додайте `#define PINOUT_WEMOS_D1_MINI_PRO` **перед усіма include**, щоб IN2 був D6. Вибір Wemos у меню Board сам по собі не змінює цей профіль підключення.

06, два мости:
- D1 → ENA і ENB разом; зняти обидві перемички.
- D2 → IN1, D5 → IN2.
- D6 → IN3, D7 → IN4.
- OUT1/OUT2 → мотор A, OUT3/OUT4 → мотор B.
- Серво не підключати до цих виходів.
Однаковий PWM не є зворотним зв'язком за швидкістю. Для точної синхронності потрібні енкодери.

## Обов'язково перед пайкою та подачею живлення

1. Зняти перемичку **ENA** (у 06 також ENB), перш ніж підключати GPIO.
2. Поставити **10 кОм між ENA і GND** біля L298N. Для 06 — на спільну лінію ENA+ENB. Він тримає міст вимкненим, поки ESP перезапускається або прошивається і GPIO ще не керується кодом.
3. Не використовувати D3/GPIO0, D4/GPIO2, D8/GPIO15 для цієї периферії. Не підключати її до RX/TX, RST/EN і контактів flash-пам'яті.
4. На GPIO ESP — тільки логічні рівні 3,3 В. **Ніколи не подавати 5 В на IN-піни ESP.**
5. З'єднати GND ESP, L298N, серво та всіх джерел. Силовий струм моторів/серво не вести через тонку землю плати ESP.
6. Не живити мотор або серво від 3V3 ESP. 5 В регулятора на модулі L298N не вважати автоматично придатними для ESP + серво: потрібні запас струму при пуску, охолодження і перевірка просідання напруги.
7. Перемичка **5V-EN/5V regulator** на драйвері — НЕ ENA. Підключення зовнішніх 5 В залежить від конкретного модуля; не з'єднувати виходи двох регуляторів. Перевірте схему свого L298N-модуля.
8. На час USB-прошивання відключити зовнішню подачу 5 В на ESP і силове живлення моторів/серво. Сигнальні дроти можна залишити за наявності коректних рівнів і ENA pulldown. Не покладайтеся на захист від зворотного живлення у невідомого клона.
9. Для робочого механізму передбачити фізичне відключення живлення приводів. STOP на сайті не працює при завислій/знеструмленій ESP та не усуває інерцію.

Відповідність GPIO: [Wemos](https://www.wemos.cc/en/latest/d1/d1_mini_pro.html). Завантажувальні піни: [Espressif](https://docs.espressif.com/projects/esptool/en/latest/esp8266/advanced-topics/boot-mode-selection.html).

## Arduino IDE та бібліотеки

- Пакет плат **ESP8266 Community 3.1.2**. URL менеджера: https://arduino.esp8266.com/stable/package_esp8266com_index.json
- **WebSockets by Markus Sattler 2.7.3** та **ArduinoJson by Benoit Blanchon 7.4.3** для 01/03/06/07.
- ESP8266WiFi, ESP8266WebServer, DNSServer, ESP8266mDNS, ESP-NOW і генератор імпульсів серво входять у пакет ESP8266. Окрема Servo-бібліотека не потрібна.
- CPU: 80 MHz. Upload Speed: почати з 115200. Serial Monitor: 115200.
- Для NodeMCU v3 обирати NodeMCU **1.0**, не 0.9. Для Wemos — D1 mini Pro; 16 MB лише якщо це реальна ємність flash (у вашому логу визначено 16 MB).
- Не змінювати наосліп MMU, flash mode або частоти як «лікування». Профілі плати мають власні параметри.
- Якщо компілятор скаржиться на шлях з кирилицею, перенесіть Sketchbook/бібліотеки у простий шлях латиницею, наприклад `C:/Arduino`. Саме такий збій шляху був відтворений під час перевірки на цьому ПК.

Upload Speed не зобов'язана збігатися з Serial Monitor. Початкові повідомлення ROM ESP8266 читаються на 74880 baud, а повідомлення цієї програми — на 115200.

## Порядок першої перевірки

1. Без моторів і серво, від USB: прошити 08_Board_Diagnostics з правильним профілем плати.
2. На 115200 мають з'явитися [BOOT], [WIFI] OK, потім щосекунди [ALIVE] зі зростанням uptime. Телефон має бачити **Motor-Diagnostic**, пароль **motor8266**. Цей скетч не містить сайта.
3. Залишити на 5–10 хв, кілька разів перезапустити й повторити прошивання. Миготіння LED саме по собі цього тесту не заміняє.
4. Прошити 03 або 07. Перевірити **Motor-Control**, сайт http://192.168.4.1 та стабільний Serial без навантаження.
5. Вимкнути живлення, приєднати лише L298N та мотор, спочатку перевірити на вивішеному/закріпленому механізмі. 05 автоматично починає рух через 3 с після старту!
6. Перевірити 1%, 50%, 100%, обидва напрямки, STOP. На малому PWM мотор може не зрушити — це не доказ помилки GPIO.
7. Додати серво з правильним живленням. Перший тест без механічного навантаження; переконатися, що 0/45/90° не впираються в упор.
8. Параметри серво 333 Hz і 520–2520 мкс збережені з попереднього проєкту, але їх треба звірити з паспортом саме вашого SDS2601-26G. Програма не вимірює кут і момент досягнення позиції.
9. Під час руху закрити вкладку/відключити Wi-Fi телефона: рух має зупинитися. Для двох ESP окремо вимкнути контролер і перевірити зупинку моторної плати.
10. Кілька разів перевірити запуск та перепрошивання зі спаяними сигнальними дротами й відключеним силовим живленням приводів.

Якщо 08 перезапускається навіть без периферії — не повертайтеся до моторного коду: збережіть повний лог 74880/115200, перевірте USB-кабель, 5 В/3,3 В, реальну плату/flash та автоскидання.
Ваші попередні `boot mode:(3,7)`, `rst cause:3` самі по собі **не встановлюють точну причину збою** та не доводять, що причина саме в GPIO.
Детальна діагностика: [ESP8266 Arduino Core](https://arduino-esp8266.readthedocs.io/en/latest/faq/a02-my-esp-crashes.html).

## Налаштування та межі безпеки

Власні виміри SPEED_CALIBRATION і довжину TRACK_LENGTH_M змінюйте у config.h тієї папки, яку прошиваєте. Для 07 тепер є власний config.h.
Швидкість при старті 50%, допустимо 1–100%; STOP окремо задає нуль.
Сайт показує розрахункові метри. Програмні обмеження координати не замінюють кінцевики; без датчика немає гарантії фізичної дистанції.

У цій ревізії: спільний код драйвера, перевірки конфліктних GPIO при компіляції, PWM=0 перед зміною напрямку, пауза реверсу 50 мс, плавний розгін, негайне вимкнення PWM при STOP; heartbeat вкладки та ESP-NOW, обмежений розмір JSON-команд, відсутність стартового руху серво.
Це програмні покращення, не сертифікація безпеки обладнання.
