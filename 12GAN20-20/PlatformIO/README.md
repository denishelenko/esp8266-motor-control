# Прошивання через VS Code + PlatformIO

1. Встановіть розширення **PlatformIO IDE** у VS Code.
2. Відкрийте як проєкт папку, у якій лежить цей `platformio.ini`.
3. У меню **PlatformIO → Project Tasks** виберіть профіль і натисніть **Build**, потім **Upload**. Перший запуск завантажує пакети плат і бібліотеки.

### Поточні версії та вибір прошивки

`platformio.ini` фіксує стабільну платформу Espressif32 **8.0.0** з Arduino-ESP32 **3.3.12**, `WebSockets` **2.7.2**, `ArduinoJson` **7.4.3** та платформу ESP8266 **4.2.1** для старих однокареткових плат. Це дозволяє збирати ту саму версію коду на іншому ПК. У Arduino IDE вибирайте плату `ESP32S3 Dev Module`, Flash Size `16MB`, PSRAM `OPI PSRAM` і встановіть пакет `esp32 by Espressif Systems` 3.3.12, ArduinoJson 7.4.3 та WebSockets 2.7.2.

Для поточних двох ESP32-S3: `dual_esp32s3_controller` прошиває **першу** каретку із сайтом, `dual_esp32s3_remote` — **другу** без сайту. Підключайте по черзі тільки одну плату й обирайте її профіль. На новій та раніше прошитій справній платі N16R8 процедура COM однакова; роль визначає вибраний профіль, а не сама плата. Для Home-версії з зовнішньою точкою доступу використовуйте окремі профілі `dual_home_*`.

У скетчі першої каретки `controller_state.h` містить стан, `controller_estimator.h` обчислює **оцінку** швидкості і часу, `controller_motion.h` визначає рух, зупинку й режими, `controller_hardware.h` керує фізичними виходами. У другій каретці `remote_hardware.h` містить керування мотором, сервоприводом і LED. `firmware_impl.h` лишається місцем для сайту, ESP-NOW, обробки команд і циклу програми. PlatformIO компілює ці самі Arduino-скетчі через файли у `src`, тому їх не потрібно редагувати двічі.

Поки немає енкодера чи датчика Холла, позиція та `estimatedTravelSeconds` у WebSocket-стані — лише обчислення за часом. Заповніть фактичні `TRAVEL_TIMES` у `config.h` після вимірювання 16 м вправо й вліво. Нулі там означають, що використовується тимчасова швидкість 0,8 м/с при 100%, і фізична каретка може не доїхати або переїхати ціль. Обмеження ±8 м є програмною оцінкою, не кінцевим вимикачем.

### Швидша повторна збірка

PlatformIO зберігає об'єктні файли у `.pio/build`, а налаштований у `platformio.ini` спільний кеш `.pio/cache` повторно використовує сумісні результати між профілями. Залишайте папку проєкту на тому самому місці, не запускайте **Clean** перед кожною зміною й збирайте лише потрібний профіль, наприклад `dual_esp32s3_controller`. Після зміни коду повторна збірка перекомпілює змінені файли та залежні від них частини. Перший запуск, зміна платформи, бібліотек або параметрів збірки можуть знову тривати довго. На перевіреній машині повторна збірка головної каретки тривала приблизно 6 секунд після першої успішної збірки.

### Зібрати на швидкому ПК, прошити на іншому

На швидкому ПК відкрийте PowerShell у цій папці та виконайте:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\export-controller.ps1
```

Скрипт збирає профіль `dual_esp32s3_controller` і створює повний образ для ESP32-S3 N16R8: `.pio/release/dual_esp32s3_controller-full.bin`. Перенесіть **саме цей BIN** на інший ПК. Це образ головної каретки із сайтом; для другої каретки він не підходить. На іншому ПК потрібні USB-з'єднання з платою та esptool; компілювати там не потрібно. Якщо PlatformIO вже встановлений, у PowerShell з папки, куди скопійовано BIN, виконайте (замініть COM7 на фактичний порт):

```powershell
& "$env:USERPROFILE\.platformio\penv\Scripts\python.exe" "$env:USERPROFILE\.platformio\packages\tool-esptoolpy\esptool.py" --chip esp32s3 --port COM7 --baud 115200 write-flash 0x0 ".\dual_esp32s3_controller-full.bin"
```

Якщо Windows не розпізнає USB-пристрій або не створює COM-порт, спочатку усуньте цю проблему: готовий BIN її не виправить. Не копіюйте `.pio/build` між ПК, бо це проміжні файли для збірки.

| Профіль | Плата й роль |
| --- | --- |
| `single_nodemcu` | NodeMCU v3, одна каретка та сайт |
| `single_d1_mini_pro` | Wemos D1 mini Pro, одна каретка та сайт |
| `single_esp32s3` | ESP32-S3 N16R8, одна каретка та сайт |
| `dual_esp32s3_controller` | ESP32-S3 N16R8, головна каретка та сайт |
| `dual_esp32s3_remote` | ESP32-S3 N16R8, віддалена каретка |
| `dual_home_main_serial` / `dual_home_main_ota` | Головна ESP32-S3 у зовнішній мережі `Motor-Control`, USB / OTA |
| `dual_home_remote_serial` / `dual_home_remote_ota` | Друга ESP32-S3 у тій самій мережі, USB / OTA |

Усі активні ESP32-S3 прошивки використовують однакові піни: `1` → IN1 обох мостів, `2` → IN2 обох мостів, `42` → A1 TXS0108E для сервопривода, `47` → червоний LED, `21` → зелений LED. Профілі PlatformIO підключають відповідні скетчі з папки `Arduino IDE` або `Home dev internet`, тому окремих копій пінів у `src` немає.

Для двох кареток прошийте головну й віддалену плати відповідними профілями. Для ESP32-S3 задані 16 МБ flash, OPI PSRAM і прошивання через USB-UART. Номер COM визначається автоматично. За потреби додайте `upload_port = COM6` у потрібний профіль, підставивши порт плати. Обидва профілі використовують консервативні 115200 бод для першого прошивання; Monitor теж працює на 115200 бод.

### Якщо Upload зупиняється на `Connecting... No serial data received`

Це збій зв'язку з завантажувачем до запису прошивки. Для плати **N16R8** залишайте 16 МБ flash і 8 МБ PSRAM: число 6 553 600 байтів у звіті збірки — розмір розділу для застосунку, а не розмір флеш-пам'яті. У профілі `dual_esp32s3_controller` на час першого підключення встановлено `upload_speed = 115200`; після успішного прошивання можна спробувати 460800 або 921600.

Якщо журнал не доходить до `Chip is ESP32-S3`, змінений скетч і версія бібліотеки не можуть виправити це: код ще не запущено. COM може існувати завдяки USB-UART, навіть коли сам ESP32-S3 не відповідає. Перевіряйте кабель, роз'єм UART, режим BOOT, кнопку RESET і живлення окремо; при повідомленні Windows «USB-пристрій не розпізнано» перевіряйте також нативний USB-роз'єм та плату. Перед пайкою до драйвера перевірте прошивання на окремій платі.

1. Вимкніть батарею та зовнішнє живлення приводів. Підключіть ESP32-S3 справним кабелем без USB-хаба до роз'єму **UART** плати.
2. У Windows перевірте, який COM-порт з'являється саме при підключенні цієї плати. Якщо автоматичний вибір PlatformIO помилковий, впишіть цей порт у `upload_port` профілю `dual_esp32s3_controller`.
3. Закрийте Serial Monitor та інші програми, що використовують порт. Запустіть **Upload**. Якщо на екрані `Connecting...` немає відповіді, утримуйте **BOOT**, коротко натисніть **RESET**, відпустіть RESET, потім BOOT.
4. Якщо плата досі не відповідає, спробуйте інший USB-кабель або роз'єм **USB** ESP32-S3 і знову перевірте номер COM-порту. Не міняйте розмір флешу на 32 МБ, якщо на модулі позначено N16R8.

Інструкції виробника: [ESP32-S3-DevKitC-1](https://docs.espressif.com/projects/esp-idf/en/v4.4/esp32s3/hw-reference/esp32s3/user-guide-devkitc-1.html), [esptool: No serial data received](https://docs.espressif.com/projects/esptool/en/latest/esp32s3/troubleshooting.html).

З термінала PlatformIO:

```powershell
pio run -e dual_esp32s3_controller
pio run -e dual_esp32s3_controller -t upload
pio run -e dual_esp32s3_remote -t upload
```

Редагуйте `config.h` і код у [Arduino IDE](<../Arduino IDE>). Файли в `src` підключають відповідні скетчі, тому обидва середовища збирають одні й ті самі вихідні файли. Під час копіювання проєкту збережіть обидві папки поруч.

Для окремої Home-версії редагуйте скетчі у [Home dev internet/2_Carriages_WebSite](<../Home dev internet/2_Carriages_WebSite>). Першу прошивку кожної плати зробіть через `*_serial`. Потім для Wi-Fi оновлення виберіть відповідний `*_ota` і натисніть **Upload**. Мережа `Motor-Control` має існувати окремо, працювати на 2,4 ГГц і фіксованому каналі 6. Якщо ім'я `motor.local` чи `motor-carriage-2.local` не знаходиться, замініть `upload_port` в `platformio.ini` на фактичну IP-адресу плати. Деталі й вимоги до OTA є в README Home-версії.
