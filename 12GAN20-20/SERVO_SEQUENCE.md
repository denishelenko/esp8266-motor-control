# Сервопривід у двох ESP32-S3

Обидві версії головної каретки (власна мережа `Motor-Control` і Home/OTA)
мають однакову структуру:

- `functions/servo_sequencer.h` — неблокувальна черга команд; її `tick(millis())`
  викликається кожного проходу `loop()` поряд із мотором, Wi-Fi та ESP-NOW.
- `programs/servo_programs.h` — приклад програми відкриття/закриття і точка,
  де задають кути та індивідуальні витримки.
- `programs/controller_motion.h` — логіка руху каретки; запускає програму сервоприводу.
- `functions/controller_hardware.h` — подає імпульси на локальний сервопривід.
- `ESP32S3_Carriage_2/functions/remote_hardware.h` — подає імпульси на сервопривід другої
  каретки після отримання кута через ESP-NOW.

Головний `firmware_impl.h` обробляє команди сайту, Wi-Fi та ESP-NOW і викликає
модулі з `functions` та `programs`. `functions/controller_estimator.h` оцінює
пройдений шлях за часом; це не покази датчика положення.

## Власна послідовність

У логіці головної плати можна запустити, наприклад, таку програму для першої
каретки:

```cpp
const ServoStep steps[] = {
    {90, 2000},  // дійти до фізичних 90°, потім стояти там 2 с
    {45, 1000},  // дійти до 45°, потім стояти там 1 с
    {0,  2000},  // дійти до 0°, потім стояти там 2 с
};
startServoSteps(carriages[0], 0, steps, 3, true, millis());
```

`true` означає повторювати; `false` — виконати один раз і залишити останній
заданий кут. Для другої каретки використайте `carriages[1], 1`. Модуль копіює
кроки у власну пам'ять, тому локальний масив `steps` безпечний. Максимум —
8 кроків. Кнопка «Вимк.» викликає `closeServo()` і задає 0°.

Для однієї команди є коротші виклики:

```cpp
moveServoTo(carriages[0], 0, 90, millis());       // 90° без таймера
holdServoAt(carriages[0], 0, 45, 1000, millis()); // 45° і витримка 1 с
```

Наступну команду після `holdServoAt` треба запускати за завершенням
послідовності, перевіряючи `carriages[0].servo.active()` у `loop()`; самі
команди не блокують виконання коду. Якщо потрібні кілька послідовних кутів,
зручніше задати їх одним масивом `ServoStep`.

Час у другому полі — **витримка після оціненого завершення повороту**. Третім
полем можна задати тривалість конкретного руху в мілісекундах, наприклад
`{90, 2000, 480}`. Без третього поля модуль масштабує виміряний час для 90°
за різницею кутів. Час відкриття й повернення для кожної каретки задається
окремо в `config.h`: `SERVO_TRAVEL_90_MS[2]` і `SERVO_RETURN_90_MS[2]`.
Поточні 350 мс — лише початкова оцінка. Заміряйте фізичний час 0→90° і
90→0° під реальним навантаженням, окремо для кожної каретки.

Наявний сервопривід емпірично повертається приблизно на 90 фізичних градусів
від команди 180°. Тому апаратний модуль перетворює фізичний кут 0–90° на
команду 0–180°. Це калібрування конкретного сервоприводу, а не стандартна
властивість усіх сервоприводів.

Без датчика положення контролер **не знає**, коли вал фактично досягнув кута.
Отже, дві секунди витримки починаються після *розрахованого* часу руху.
Точність залежить від виміряного часу, напруги й навантаження. Під час
роботи кроків `loop()` продовжує обробляти мотор, сайт і радіозв'язок;
`delay()` для сервоприводу не використовується.
